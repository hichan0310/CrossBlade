# 온라인 1대1 테스트

전투 계산은 호스트 PC가 맡고 Unity Relay는 통신을 중계합니다. 전용 서버를 띄우지 않습니다. `CombatScene`은 기존 로컬 전투용이고 `OnlineCombat`은 온라인 전용 씬입니다.

## 실행

1. Unity가 Multiplayer Services / Netcode for GameObjects 패키지를 임포트하도록 기다립니다.
2. **Tools > CrossBlade > Prepare Online Duel**을 실행합니다. 온라인 씬과 빌드 호환성 지문을 준비합니다.
3. `Assets/Scenes/OnlineCombat.unity`를 열고 Play를 누릅니다.
4. 한쪽은 **비공개 방 만들기**, 다른 쪽은 **방 코드로 참가**를 누릅니다. 또는 양쪽에서 **대전 찾기 (Quick Join)**를 누릅니다.
5. 호스트는 왼쪽, 참가자는 오른쪽 캐릭터를 조작합니다. 준비·차지 행동 중 스페이스를 눌러 힘을 모으고, 다음 행동 버튼을 누릅니다.

호스트가 선택 제한 시간을 관리합니다. 현재 테스트 규칙은 3초이며, 시간 초과 시 그래프에서 Idle 동작으로 체크한 Move로 돌아갑니다. Idle 체크는 그래프에서 정확히 하나여야 합니다. 기존 그래프 연결과 공통 방어·피격을 사용합니다. 상대가 확정한 다음 행동은 실행 전에 전송하지 않습니다. 스페이스 충전은 호스트에서 자세 비용·충전 가능 Move·힘 상한을 검증합니다. 호스트는 양쪽 상태를 알고 있으므로 부정행위 방지용 경쟁전 구조는 아닙니다.

준비·차지 동작에서 다음 행동을 결정하기 전에 스페이스로 힘을 모읍니다. 공격에서 힘 1당 자세 5를 사용하며, 모든 행동 종료 시 자세 10, idle 종료 시 총 15를 회복합니다.

현재 행동 중에도 다음 행동을 큐에 넣고, 큐 마지막 행동의 후보를 계속 추가할 수 있습니다. 큐에 행동이 있으면 시간 초과로 Idle을 덧붙이지 않습니다. 다음 행동을 확정하면 그 행동의 추가 충전은 잠기며, 행동 종료 때 큐가 비면 저장된 힘은 사라집니다.

대기 큐는 최대 5개입니다. 새 행동을 추가할 때 이미 대기 중인 행동 수 × 5를 해당 행동의 자세 회복 보너스로 고정합니다. 행동이 정상 종료할 때 이 보너스를 기본 회복량에 더합니다. 예를 들어 대기 행동이 2개일 때 추가한 행동은 종료 시 자세 +10을 추가로 회복합니다. 화면에 큐 길이와 다음 추가 행동의 보너스를 표시하며, 호스트가 큐 상한을 검사합니다.

전투 중 각자 **← / →**로 자신의 추격·전진·넉백 방향 보정을 입력할 수 있습니다. 현재 속도의 20%를 계산하고, 그 **변화량의 절댓값**에 Actor의 최소·최대 제한을 적용한 뒤 같은 방향이면 더하고 반대 방향이면 뺍니다. 최종 속도 자체는 제한하지 않습니다. `NewMoveIdle`에서는 방향키로 직접 걷고, 행동 중에도 입력 방향을 즉시 바꿀 수 있습니다. 참가자의 방향 입력은 호스트에 전달되며 최종 위치는 호스트가 계산합니다.

넉백은 Move별 `기본 위력 + 힘 1당 추가 위력 × 실제 사용한 힘`으로 양쪽 위력을 구한 뒤, 받는 쪽의 기본 이동 거리 `max(0, 0.04 × 상대 위력 + 0.02 × (상대 위력 - 내 위력))`를 계산합니다. 호스트가 약 0.33초 동안 이 거리를 감속 적용하며, 방향키 입력은 각 프레임 이동량에 반영됩니다.

매칭 도중 **매칭 / 접속 취소**를 누르면 진행 중인 서비스 요청이 끝나는 대로 생성·참가한 세션을 정리합니다. **나가기 / 다시 시작**으로 초기 화면으로 돌아갑니다. 접속이 끊기면 경기를 중단하며 호스트 이전·재접속 복구는 지원하지 않습니다. 테스트 경기는 5분 제한이고, 종료 후 10초가 지나면 연결을 해제합니다.

## Unity 서비스 설정

프로젝트는 `ProjectCrossblade` Cloud Project ID에 연결돼 있습니다. Unity Dashboard에서 해당 프로젝트의 Authentication 익명 로그인과 Multiplayer의 Lobby/Relay 이용 가능 상태를 확인해야 합니다. 코드가 결제 수단이나 유료 플랜을 등록하지는 않습니다.

Editor와 플레이어 빌드는 서로 다른 인증 프로필을 사용합니다. 한 컴퓨터에서 플레이어 두 개를 실행할 때는 각각 `-onlineProfile player1`, `-onlineProfile player2` 인자를 사용하세요. 두 클라이언트 모두 동일한 그래프·모션·전투 코드 빌드여야 합니다.

Quick Join은 동일한 콘텐츠 지문의 공개 방을 찾고, 5초 안에 찾지 못하면 새 공개 방을 만듭니다. 실력·지역 기반 랭크 매칭은 포함하지 않습니다. 비공개 방은 코드로만 참가합니다. 최대 인원은 호스트 포함 2명입니다.

현재 무료 요금은 서비스의 월평균 접속 시간·트래픽 등 사용량 조건입니다. 이 구현이 무료 한도 안에서만 자동으로 운영되거나 과금을 자동 차단하는 것은 아닙니다. Dashboard에서 Relay/Lobby 사용량을 확인하고 소규모 비공개 테스트부터 시작하세요. [Unity 요금표](https://unity.com/products/gaming-services/pricing).

## 로컬 연결 검증

UGS 없이 통신 자체를 확인하려면 **개발용 로컬 접속**을 켭니다. 호스트는 **로컬 호스트 :7777**, 참가자는 호스트의 주소를 넣고 **로컬 참가**를 누릅니다. 같은 PC의 Editor와 빌드 조합은 `127.0.0.1`을 사용합니다. 로컬 성공은 인터넷 Relay 성공을 의미하지 않습니다.

Linux 테스트 빌드용 에디터 실행 메서드는 `OnlineDuelSetup.BuildLinuxTest`입니다. `/tmp/crossblade-online-player/CrossBlade.x86_64`에 온라인 씬만 포함한 Development 빌드를 생성합니다. 일반 빌드에서는 Build Profiles의 첫 씬을 `OnlineCombat`으로 지정하세요.

Development 빌드의 자동 검증 인자:

```text
-batchmode -nographics -duelRole local-host -duelAutoTest
-batchmode -nographics -duelRole local-join -duelAutoTest
```

20초간 유효 후보를 선택하며 동작한 뒤 결과를 `ONLINE_PROCESS_TEST` 로그에 남기고 종료합니다. 입력 검증은 격리된 프로젝트에서 `OnlineDuelValidation.Run`으로 검사합니다.

## 구현 범위

### 확인한 동작

Linux Development 빌드와 로컬 두 프로세스 연결, 잘못된 후보·힘·기한·중복 입력 검증을 통과했습니다. 실제 Unity Relay의 비공개 방 생성과 코드 참가도 독립 실행 파일 두 개로 확인했습니다. 해당 테스트에서 호스트는 입력 36건을 처리하고 상태 메시지 110건을 전송했으며, 참가자가 110건을 수신했습니다. 상태 메시지 본문 합계는 11,250바이트로, 서비스 및 전송 계층의 부가 트래픽은 제외한 수치입니다.

두 프로세스는 같은 PC에서 실행했습니다. 지역 간 지연, 대규모 동시 접속, Quick Join의 여러 사용자 동시 검색은 아직 실환경 검증하지 않았습니다. 이 결과로 무료 수용 인원을 확정할 수는 없습니다.

### 전투 동기화

- 호스트에서 기존 `ActorManager`를 고정 시간 간격으로 실행합니다. 참가자는 전투 판정을 실행하지 않습니다.
- 호스트가 접속 자리·선택 구간 번호·행동 후보·고정 기본 힘·마감·중복 입력을 검증합니다. 피격 등으로 행동이 바뀌면 이전 선택 구간은 무효가 됩니다.
- 10Hz의 이진 상태 메시지로 양쪽 위치·행동·진행률·HP·자세·현재 힘과 자기 입력 후보를 전달합니다. 참가자는 위치를 보간하고 애니메이션 진행률을 짧게 보정합니다. 롤백 예측은 포함하지 않습니다.
- 에디터 준비·온라인 씬 Play·빌드 시 콘텐츠 지문을 갱신합니다. 현재 그래프와 연결 대상이 다르면 준비 단계에서 오류를 표시합니다. 서로 다른 콘텐츠 지문은 접속과 자동 매칭에서 제외합니다.
- 별도 데이터베이스, 랭킹 저장, 승패 인증, 호스트 이전, 관전은 아직 없습니다.

서비스 API: [세션 생성](https://docs.unity.com/en-us/mps-sdk/create-session), [Quick Join](https://docs.unity.com/en-us/mps-sdk/matchmake-lobby).
