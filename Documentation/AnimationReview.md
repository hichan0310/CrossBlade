# 애니메이션 편집과 Move 만들기

몸의 피격 판정은 Combat Move Graph에서 노드를 선택한 뒤 미리보기 위 **몸 피격 판정** 탭에서 편집합니다. 없으면 **몸 피격 박스 만들기**를 누르고, 박스 내부·모서리를 드래그하거나 중심·크기를 입력한 뒤 **Move 저장**하세요. 무기 공격 판정과 구분하여 실제 몸 콜라이더에 저장됩니다.

방어·피격 연결선을 줄이려면 Combat Move Graph 오른쪽 상단 **공통 방어 / 공통 피격** 드롭다운에서 현재 그래프의 노드를 선택하세요. 개별 연결이 있으면 우선하고, 없으면 해당 그래프에 저장된 공통값을 따릅니다. **공통값과 같은 개별 연결 정리**로 중복 연결만 제거할 수 있습니다. 실제 전투에 사용할 그래프는 캐릭터의 **Actor > Combat Move Graph**에 지정합니다. [공통 방어·피격 사용법](CombatMoveGraph.md)을 참고하세요.

## 자르기·배속 조절 후 .anim 내보내기

타임라인은 편집 결과의 0초부터 시작합니다. 길이는 `(끝 프레임 - 시작 프레임) / 원본 FPS / 배속`이며 프레임 이동도 출력 FPS 기준입니다. 예를 들어 30 FPS 원본의 30–90 프레임을 2배속으로 설정하면 타임라인은 0–1초입니다. 전체 원본을 다시 확인할 때만 **원본 전체 확인**을 켜세요. 시작·끝 프레임을 수정하면 다시 편집 구간으로 전환됩니다.

**CrossBlade > Elden Ring Motion Library** 안에서 모두 처리할 수 있습니다. 모션을 선택하고 미리보기 아래 **시작 프레임 / 끝 프레임 / 재생·내보내기 배속**을 조절하세요. 선택 구간을 반복 재생해 확인한 뒤 **선택 구간을 .anim으로 내보내기**를 누릅니다. 배속은 미리보기와 저장 결과에 동일하게 적용됩니다. 현재 프레임을 시작·끝으로 지정하는 버튼과 단축키 **I / O**, 내보내기 단축키 **C**도 있습니다.

편집하면 자동 다음 모션 재생이 해제됩니다. 같은 창을 열어 둔 동안에는 후보별 구간과 배속을 기억합니다. 루트 모션 체크도 내보내기에 적용되며 기존 파일은 덮어쓰지 않습니다.

**CrossBlade > Motion Composer**에서 원본 클립을 추가하거나 기존 편집 `.asset`을 불러옵니다. **시작 프레임 / 끝 프레임 / 저장할 재생 속도**를 조절한 뒤, 창 맨 위의 **.anim 내보내기 · 자르기 / 배속 적용**을 누릅니다. Move 생성이나 편집 `.asset` 저장 없이 애니메이션만 저장할 수 있습니다.

## Move 만들기

1. 라이브러리에서 내보낸 `.anim`을 Project에서 선택하고 **CrossBlade > Combat Move Graph > 애니메이션 → Move**를 누릅니다.
2. **원본 애니메이션**에 클립을 넣고 **추가**를 누릅니다. FBX는 Project에서 펼친 뒤 내부 클립을 넣습니다.
3. 미리보기를 보면서 **시작 프레임**, **끝 프레임**, **저장할 재생 속도**를 조절합니다.
4. 창 위의 **Move 만들기 · 전투 그래프에 추가**를 누르고 프리팹 이름을 지정합니다. 같은 폴더에 `.anim`과 `.prefab`이 생성되고, 애니메이션과 길이가 지정된 Move가 그래프에 추가됩니다.
5. 그래프에서 다음 행동·방어·피격 연결과 이동·히트박스를 설정하고 그래프를 저장합니다. 새 노드의 전투 연결은 자동으로 만들지 않습니다.

이미 잘라 저장한 `.asset`은 **더블클릭**하거나 **저장한 편집 (.asset)**에 넣은 다음 바로 **Move 만들기**를 누르면 됩니다. 편집 `.asset` 저장과 `.anim` 수동 내보내기는 선택 사항입니다. 새 클립을 라이브러리에서 열면 독립된 편집으로 시작합니다.

CrossBlade 메뉴에는 **Elden Ring Motion Library**, **Motion Composer**, **Combat Move Graph**가 있습니다. Motion Composer는 자르기·배속·애니메이션 내보내기 도구입니다. 이전 시퀀스 설계용 Motion Graph / 별도 Move 편집기 / 샘플 / Danjin 검토 메뉴는 제거했습니다. 기존 에셋과 편집 데이터는 유지합니다.

아래는 이전 Danjin 임포트 도구에 대한 보관용 문서입니다. 현재 Move 생성에는 아래 승인 절차와 메뉴를 사용하지 않습니다.

## 이전 애니메이션 임포트 및 수동 검토 (보관)

**빈 Move 생성·히트박스·연속 모션의 X/Y 이동 편집**은 [전투 행동 편집 사용법](CombatMoveGraph.md)을 참고하세요. **CrossBlade > Combat Move Graph**에서 노드를 선택하면 오른쪽에서 모션·이동·판정 구간을 함께 편집할 수 있습니다. 별도 재생 목록은 필요하지 않습니다.

실제 전투 행동의 다음 후보·방어·피격 분기는 **CrossBlade > Combat Move Graph**에서 편집합니다. [전투 행동 그래프 사용법](CombatMoveGraph.md)을 참고하세요.

> 수천 개의 엘든링 원본 모션을 찾고, 자르고, 속도를 바꾸고, 합치는 작업도 현재 CrossBlade 프로젝트에서 진행합니다. 이 문서는 그렇게 확정한 모션을 Danjin으로 리타게팅한 뒤 검토하는 마지막 단계에 관한 문서입니다. 앞 단계는 [CrossBlade 엘든링 대량 모션 워크플로](EldenRingMotionWorkflow.md)를 참고하세요.

**CrossBlade > Animation Review**를 열면 됩니다. Danjin 프로필과 실제 캐릭터는 이미 연결되어 있으므로, 애니메이션을 추가할 때마다 Avatar를 지정하거나 프리팹을 다시 만들 필요가 없습니다.

문서의 메뉴와 버튼 이름은 Unity 화면에서 쉽게 찾을 수 있도록 영어 표기를 유지했습니다.

## 새 FBX를 가져오는 순서

1. 기존 Danjin의 Generic 스켈레톤에 맞춰 애니메이션을 내보냅니다. 검증된 FBX와 같은 계층 구조, 본 이름, 단위, 축 설정을 유지하세요. 이 임포터는 다른 스켈레톤의 애니메이션을 자동으로 리타게팅하지 않습니다.
2. FBX를 `Assets/Characters/Danjin/Animations/Incoming/`에 넣습니다.
3. Unity의 임포트가 끝나면 **CrossBlade > Animation Review**를 엽니다.
4. 최근 목록에서 FBX를 선택합니다. 여러 클립이 들어 있다면 **Take**에서 원하는 클립을 고릅니다. **FBX or clip** 필드에 FBX나 클립을 직접 드래그해도 됩니다. 기존 베기 애니메이션은 Incoming에 복사하지 않아도 참고용으로 선택할 수 있습니다.
5. 재생, 일시 정지, 정지, 속도 변경, 반복 재생, 타임라인 이동, 프레임 단위 이동으로 동작을 확인합니다. 좌우 방향과 카메라 프리셋을 바꿔 가며 살펴보세요. 뷰포트를 드래그하면 시점이 회전하고, 스크롤하면 확대·축소됩니다. 손잡이와 칼날이 잘 보이도록 배경색도 바꿀 수 있습니다.
6. 만족스러우면 **Approve snapshot…**을 누르고 승인합니다. `Assets/Characters/Danjin/Animations/Approved/`에 새 `.anim` 파일이 저장됩니다. 마음에 들지 않으면 승인하지 않은 상태로 두고 외부 도구에서 수정한 뒤 다시 내보내세요. 승인은 자동으로 이루어지지 않습니다.
7. **Assign to existing Move**에서 기존 Move를 선택한 다음 **Assign approved clip**을 누릅니다. 해당 Move의 기존 `characterAnimation` 필드만 변경됩니다. 프리팹은 즉시 저장되므로, 되돌려야 한다면 소스 관리를 이용하세요.

Incoming의 FBX를 다시 내보내면 그 안의 클립은 갱신되지만, 이미 승인한 스냅샷은 바뀌지 않습니다. 승인할 때마다 고유한 파일 이름으로 새 스냅샷이 생성됩니다. 스냅샷의 `.meta`에는 원본 에셋 GUID, 테이크 ID와 이름이 기록되며, 검토 창에서도 원본 정보를 확인할 수 있습니다.

애니메이션을 교체하려면 새 버전을 다시 검토하고 승인한 뒤 Move에 직접 할당하세요. `.meta` 파일은 에셋과 함께 보관하고, GUID가 유지되도록 이름 변경이나 이동은 Unity 안에서 진행하세요. 원본 FBX와 `.meta`, 승인한 클립과 `.meta`, 변경한 Move 프리팹을 Git에 커밋하면 됩니다. 임시 미리보기 인스턴스나 테스트용 복제 에셋은 커밋할 필요가 없습니다.

## 조작 방식과 미리보기 동작

임시 Move를 이용해 기존 `CharacterAnimationPlayer`로 지정한 시점의 포즈를 직접 샘플링합니다. 샘플러에는 `seconds / clip.length`를 전달하므로 Animator 상태 머신이 해당 시점에 도달할 때까지 기다리지 않습니다.

- **Play**: 에디터에서 흐른 시간에 미리보기 속도를 곱해 재생합니다.
- **Pause**: 현재 시점에서 멈춥니다.
- **Stop / Reset**: 처음으로 돌아갑니다.
- **Loop**: 미리보기만 반복 재생합니다. 원본 에셋의 반복 설정은 변경하지 않습니다.
- 반복 재생을 끄면 마지막 프레임에서 멈춥니다.

프레임 단위 이동 간격은 `1 / clip.frameRate`입니다. 프레임 번호는 0부터 시작하며 마지막 시점도 포함합니다. 현재 베기 클립은 2.1초, 30 FPS이므로 프레임 번호는 0–63이고, 총 64개의 샘플이 있습니다. 타임라인에는 초 단위 시간, 정규화된 시간, 현재 프레임과 마지막 프레임이 표시됩니다. 메타데이터에는 원본 에셋 경로, 테이크 이름, 길이와 프레임 레이트, 에셋의 반복 여부, 루트 커브 정보가 표시되며, FBX라면 루트 및 베이크 설정도 확인할 수 있습니다.

캐릭터는 실제 지속형 프리팹에서 생성되어 임시 에디터 미리보기 씬에 배치됩니다. 실제 스켈레톤, Animator/Avatar, 스킨 메시, 머티리얼과 검을 그대로 사용합니다. 미리보기, 창 닫기, 리로드, Play 모드 전환 과정에서 캐릭터 변경 사항을 저장하지 않습니다. Play 모드에 들어가면 검토 창의 미리보기 사용이 중단되며, 기존 CombatScene은 독립적으로 동작합니다.

좌우 방향 전환에는 런타임 `CharacterAnimationPlayer`의 Y축 회전과 오른쪽 방향 기준 각도를 그대로 사용합니다. 스킨 메시에 음수 스케일을 적용하지 않습니다. **Gameplay** 시점은 게임의 관찰 방향을 유지하고, 정면·후면·측면 프리셋은 캐릭터가 바라보는 방향을 따라갑니다. 수평 루트 위치 고정도 기존 런타임 동작과 같으므로, 자유롭게 이동하는 루트 모션이 아니라 게임에서 실제로 표시되는 포즈를 확인하는 미리보기입니다.

프로필의 고정 부착 경로는 검 오브젝트에 적용된 로컬 트랜스폼 보정을 보호합니다. 해당 경로와 그 하위 오브젝트를 대상으로 하는 애니메이션 커브는 임시 미리보기 클립과 승인 스냅샷에서 제거합니다. 손과 무기 본의 애니메이션은 유지하며, 보정용 프레임 키를 추가하지 않습니다. 따라서 기존 X/Y축 그립 보정이 미리보기와 승인 클립 재생 모두에서 유지됩니다. 원본 FBX는 변경하지 않습니다.

승인 스냅샷에서 거의 변하지 않는 보조 채널은 기존 임포터와 같은 기준으로 축약합니다. 성분별 변화량 기준은 `1e-6`이며, 값이 변하는 몸체 애니메이션 커브는 유지합니다.

## 자동 임포트 설정과 적용 범위

프로필의 Incoming 폴더 아래에 있는 `.fbx` 파일만 자동 설정 대상입니다. Danjin은 기존에 검증된 Generic 모델 FBX를 기준으로 사용합니다. 임포터는 기준 FBX의 계층 보존, 모션 노드, 애니메이션 압축, 커브 리샘플링, 파일·단위 스케일, 축 변환 설정을 복사합니다. 애니메이션 임포트는 켜고 계층 최적화는 끕니다.

새 테이크는 기본적으로 반복 재생을 끄고 기준 FBX의 루트 베이크 옵션을 따릅니다. 이후 사용자가 직접 지정한 테이크 분할, 반복 여부, 루트 설정은 재임포트해도 유지됩니다. 단, Incoming 안에서는 모델 수준의 기준 설정이 계속 적용됩니다.

카메라, 조명, 머티리얼 임포트는 끕니다. 지오메트리를 제거하면 계층이나 바인드 포즈 데이터가 달라질 수 있으므로 지오메트리는 유지합니다. 미리보기에는 임포트한 애니메이션 파일의 메시 대신 실제 캐릭터와 그 머티리얼을 사용합니다.

Generic 애니메이션은 트랜스폼 경로가 일치해야 합니다. Avatar를 재사용하더라도 서로 다른 본 경로가 자동으로 호환되지는 않습니다. 따라서 Incoming의 각 FBX는 자체 Generic Avatar를 생성하고, 미리보기는 실제 캐릭터의 Avatar를 유지합니다. 연결할 수 없는 경로가 있으면 검토 창에 표시하고 승인을 막습니다. 외부 도구에서 이 스켈레톤에 맞게 내보내거나 리타게팅한 뒤 임포트하세요. 현재 워크플로는 Humanoid 머슬 클립을 지원하지 않습니다.

임포트 기본값은 Unity의 [OnPreprocessAnimation/clipAnimations 방식](https://docs.unity.cn/ScriptReference/ModelImporter-clipAnimations.html)을 사용합니다. 뷰포트는 Unity의 [PreviewRenderUtility](https://github.com/Unity-Technologies/UnityCsReference/blob/master/Editor/Mono/Inspector/PreviewRenderUtility.cs)를 사용하며, SRP 렌더링과 렌더마다 스킨 행렬을 갱신하는 설정을 적용합니다.

## 다른 캐릭터에 적용하기

**Assets > Create > CrossBlade > Animation Review Profile**에서 프로필을 만듭니다. 다음 항목을 지정한 뒤 검토 창에서 해당 프로필을 선택하세요.

- 기존 `CharacterAnimationPlayer`가 있는 지속형 미리보기 프리팹
- 임포트 기준으로 사용할 검증된 Generic 모델
- 참고용 애니메이션 클립
- 해당 캐릭터 전용 Incoming 및 Approved 폴더
- 필요한 경우 `animationRoot` 기준의 고정 부착 경로

폴더와 프리팹은 GUID 참조를 사용하는 공유 에셋으로 연결됩니다. 별도의 캐릭터 데이터베이스나 런타임 애니메이션 연결 계층은 추가하지 않습니다. 프로필끼리 Incoming 폴더 범위가 겹치지 않도록 설정하세요.

## 구현 파일과 테스트

새 코드는 모두 `Assets/Editor/AnimationReview/` 아래에 있으며 에디터 전용입니다.

- `CharacterAnimationProfile.cs`: 공유 폴더, 프리팹, 임포트 기준 및 부착 경로 설정
- `CharacterAnimationImporter.cs`: 지정된 폴더에만 적용하는 FBX 임포트 기본값
- `AnimationReviewSession.cs`: 임시 씬, 기존 런타임 샘플러 연결, 재생 및 카메라 제어
- `AnimationReviewAssets.cs`: 테이크 검색, 호환성 검사, 고정 부착 경로 필터링, 승인 및 프리팹 할당
- `AnimationReviewWindow.cs`: 수동 검토 UI
- `DanjinReviewSetup.cs`: 실제 에셋으로 초기 프로필 구성. 기존 설정은 덮어쓰지 않음
- `AnimationReviewValidation.cs`: 임시 에셋으로 조작, 임포트, 승인 및 할당 검증
- `AnimationReviewGraphicsValidation.cs`: 실제 뷰포트의 포즈 및 카메라 프리셋 캡처

공유 프로필은 `Assets/Characters/Danjin/DanjinAnimationReview.asset`입니다. 이 도구를 추가하면서 기존 런타임 스크립트, 실제 캐릭터 프리팹, Attack1_1, CombatScene, 전투 로직이나 충돌 처리는 변경하지 않았습니다.

배치 실행 시 `-projectPath`로 이 Unity 프로젝트를 지정하고, `-logFile`로 로그 저장 위치를 지정합니다.

- `CrossBlade.EditorTools.AnimationReviewValidation.Run`: `-batchmode -nographics -quit`로 실행합니다.
- `CrossBlade.EditorTools.AnimationReviewGraphicsValidation.Run`: 그래픽 사용이 가능한 환경에서 `-batchmode -quit`로 실행합니다.
- 기존 `DanjinIntegrationValidation.Run`: Play 모드에 들어간 뒤 스스로 종료하므로 `-quit`를 붙이지 않습니다.

로그와 결과는 작업 공간의 `output/unity_integration/`에 저장됩니다.
